## Администрирование и права

Четырём существующим аккаунтам из списка Дмитрия выданы и прочитаны обратно `admin:true`; остальные claims сохранены. Дополнительно сохранено право одного активного прежнего администратора, которое ранее проверялось по UID в клиенте. Ещё один прежний аккаунт уже имел claim, третий отсутствует в Auth и не восстанавливался. Новые неизвестные пользователи не создавались. Личные UID и backup claims находятся только в private файлах.

В Firebase созданные индексы ленты/регионального запроса находятся в READY. В Storage опубликован временный барьер от записи без входа с сохранённым предыдущим ruleset. Действующий Firestore ruleset всё ещё разрешает чтение/запись вошедшему пользователю глобально; его нельзя считать подтверждением изоляции аккаунтов. Более строгий полный ruleset без проверки совместимости старых клиентов не публиковался. Cloud Functions не менялись.

## Ограничения перед переключением

Нужны полный архив и побайтовый импорт в приватный S3, сверка MySQL/медиа с одним и тем же архивом, полноценный runtime API, адаптация Flutter, реальные сценарии двух аккаунтов, restart/backup/restore/rollback. Текущий APK остаётся на Firebase, тестирование на локальных Firebase эмуляторах не доказывает работу Timeweb или production rules.

Существующий публичный S3 нельзя заполнять приватными фото. Старый Flask `POST /upload-photo` использовал public-read и прямые ссылки; одного совпадающего bucket UUID недостаточно для вывода о владельце старого объекта. Сначала сохранить объект и проверить потребителей ссылок.

Без новых платных услуг использованы существующий MySQL и бесплатный App Platform стенд. 10 ГБ S3 номинально вмещают один исходный набор 6,9 ГБ, но не второй полный backup. Независимый encrypted backup должен храниться вне этого бакета. Новые услуги, повышение тарифов и платные бэкапы автоматически не включались. Расходы на исходящий трафик не обещаются нулевыми.
