# Проверка TLS с runtime Python

2026-09-30 Node 22/mysql2 и Python 3.12.14 смогли установить настоящее
TLS-соединение с тестовой `clrs_staging`, официальным CA Timeweb и ролью
`clrs_api_ro`, выполняющей только SELECT. Python 3.12.14/OpenSSL 3.5.8
успешно выполнил SELECT 1, cipher TLS_AES_256_GCM_SHA384.
Контекст создан через `ssl.create_default_context(cafile=...)`; значения
`verify_mode == ssl.CERT_REQUIRED`, `check_hostname == True` сохранены,
`verify_flags` не изменялись (default VERIFY_X509_TRUSTED_FIRST, 32768).
Реквизиты читались из файла `0600`; их значений нет в командах и отчёте.

На фактическом App Platform runtime Python 3.14.7/OpenSSL 3.5.7 тот же
сертификат вызвал отказ проверки с отсутствующим Authority Key Identifier.
Причина — требования строгого X.509 в новых версиях Python, а не пароль
или права SELECT. Проверку сертификата/имени не отключать и флаги контекста
не ослаблять. Для стенда использовать поддерживаемый Python 3.12 с его
обычным TLS-контекстом и после развёртывания отдельно проверить `/readyz`.
Если 3.12 в Timeweb недоступен, нужен исправленный CA/сертификат от провайдера;
обход через `CERT_NONE` или `check_hostname=False` недопустим.

Эта локальная проверка не подтверждает подключение самого развернутого
backend: его результат должен отдельно показать `database_connected:true`.
`/readyz` должен остаться 503 `migration_incomplete`, пока перенос данных
и пользовательские сценарии не завершены.

## Проверено на Timeweb, 2026-10-01

Настройки основного приложения сохранены с Python 3.12 и безопасной веткой без enable-флагов. Старый основной Flask остаётся остановленным. Стенд 5167 сохранил runtime 3.14; изменение общих настроек не пересобрало его runtime. Создан второй **бесплатный** стенд 5179 после выбора 3.12, с теми же четырьмя переменными только для стенда.

На `https://4ekhytblyi-python-server-stand-f41f.twc1.net/readyz` получен HTTP 503 с `state:migration_incomplete`, **`database_connected:true`**. Это реальный SELECT 1 из развёрнутого backend с исходным CERT_REQUIRED / hostname verification. Проверка сертификата не ослаблялась. `/healthz` — 200 api_draft. Подключение к БД подтверждено; реальный профиль, перенос данных и пользовательские сценарии ещё не подтверждены.
