# CLRS infrastructure smoke API

This image is **only** a deployment and database-connectivity probe. It does not serve CLRS users, authentication, profiles, photos, chats, gifts, meetings or admin actions. A successful probe must never be reported as a migrated app or a working APK.

`GET /healthz` returns 200 when the process is alive. `GET /readyz` performs a bounded `SELECT 1` over a verified TLS PostgreSQL or MySQL connection and returns 200 only if it succeeds. Without `DATABASE_URL`, with an invalid URL/CA, or when the database cannot be reached, readiness returns 503. Every other path returns 404; other methods on these two paths return 405. No endpoint reads or writes user records.

Configuration: `PORT` (default 8080), `DATABASE_URL` (URL with user, password, host and **explicit database**), and `DATABASE_CA_FILE` (server CA certificate mounted outside the image). The existing PostgreSQL configuration still accepts the system trust store when `DATABASE_CA_FILE` is absent. For the existing Timeweb MySQL 8.4 staging database, use a `mysql://` URL ending in `/clrs_staging` with `?sslmode=verify-full` and provide `DATABASE_CA_FILE`; another database name, including `default_db`, is rejected. Use the database's DNS hostname matching its TLS certificate; a literal IP address is rejected for MySQL. MySQL defaults to port 3306 and PostgreSQL to 5432. TLS certificate and hostname validation are always enabled; insecure or unknown URL options are rejected. Store credentials in a protected env file outside git and mount the CA read-only. Never pass secrets as Docker build args. No connection string or database error is logged or returned.

Build, test and publish a reviewed image; pin its digest in the separate staging Compose configuration. The container runs as the unprivileged `node` user. Its filesystem can be read-only, as in `deploy/compose.yaml`. This source does not create Timeweb resources or change the existing Flask/Firebase services.

Local checks: `npm ci`, `npm test`, `docker build -t clrs-infra-smoke:local .` (if Docker is available). The synthetic MySQL test checks the configuration and `SELECT 1` call; it does not establish a real database connection. Real MySQL readiness needs a dedicated user with access only to `clrs_staging`, its server CA, and a reachable endpoint. Do not point this probe at the existing MySQL `default_db`.
